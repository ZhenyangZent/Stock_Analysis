# 專案交接說明

基準日 2026-10-05。這份文件讓新加入的 AI 或人不用重看整段對話。

## 這個專案在做什麼

使用者長期收看財經節目（主要是 Emmy 的會員影片），也用多個 AI 幫忙分析。問題是：
**每個 AI 每次看的資料不同、強調的重點不同，結論無法比較，也無法事後檢驗。**

目標是建立一套固定規範：
- 每次看同樣的指標、用同樣的來源、填同樣的表
- 判斷由固定規則計算，不靠模型臨場發揮
- 每次的輸入和結論都留檔，之後可以回測、可以改進規則

## 為什麼要這樣設計：這輪實際犯過的錯

這些錯誤是規範裡每一條規則的來源。

| 錯誤 | 實例 | 對應的規則 |
|---|---|---|
| 憑記憶回答 | Claude 說光通訊 SENKO 是日股 9069 旗下事業，查證後是兩家無關的公司 | 禁止用記憶中的數字與對應關係，查不到填 null |
| 數字對、意思錯 | Arista 的 97 億美元是公司對供應商的採購承諾，被寫得像客戶訂單 | 每個數字要記「誰對誰、哪個期間、哪種口徑」 |
| 實體對錯 | 磷化銦打成磷化銅；逐字稿把公司名辨識錯 | 公司一律用代號加名稱，材料與技術名詞附英文 |
| 好公司當成好買點 | 另一個 AI 給二十多家公司星等與「首選」，沒有任何估值 | 估值是獨立一層，缺估值不能得到正面結論 |
| 假分散 | 把台積電、Broadcom、Arista、Vertiv 當成分散，其實都押雲端業者資本支出 | 部位層要算同一因子的總曝險 |
| 把估計當事實 | Muse「500 萬下載」是 Sensor Tower 的估計；TrendForce 的 68% 是模型 | 每筆資料標六種類型之一 |
| 只看摘要 | 多數財報數字只看過搜尋摘錄，沒開全文 | 每筆資料標查證程度；關鍵欄位要求「已開原文」 |
| 事後諸葛 | 用後來才知道的結果評價當時的預測 | 每次執行記錄資訊截止時間 |
| 模糊預測無法評分 | 「九月有作帳行情」事前沒定義標準 | 所有判斷用固定欄位與固定門檻 |
| 過度解讀股價 | 好消息後股價跌就說預期過滿 | 股價反應一律扣掉同類指數 |
| 單一訊號當結論 | 一家雲端業者下修就說產業轉壞 | 用四家合計，分級處理 |
| 被評語帶著走 | 外部評語說 Marvell 直播時間不是官方資訊，查證後它是 | 別人的更正也要自己查過才採納 |

## 已知的限制

- 沒有即時股價來源。`prices.csv` 需要使用者或有工具的 AI 補資料。
- 試算表 83 筆主張裡只有 17 筆「已開原文」，55 筆只看過摘要。
- `rules.json` 的門檻是初始設定，**還沒有經過任何回測驗證**。
- 風險因子表是主觀評級。
- 沒有使用者的持股與部位資料，部位層目前只能算公式。
