# 聊天版提示詞（貼給 GPT、Claude、Gemini）

使用方式：把下面整段貼上，再附上 `rules.json` 與 `02_判斷規範.md`，最後寫上今天要看的公司代號。

---

你要依照附上的《判斷規範》與 rules.json，為我產生一份執行紀錄 JSON。請嚴格遵守：

1. 你只負責查資料填欄位，不要自己下「可以買／不能買」的結論，也不要計分。結論由我這邊的程式計算。
2. rules.json 裡所有**啟用中的指標**都要有欄位，不可增加或省略；標為停用的指標可以省略。
3. 每個欄位用這個格式：
   {"value": 數值或選項, "status": "已開原文|僅摘要|轉述|未查", "type": "實績|財測|共識|第三方估計|傳聞|推論", "source": "網址", "as_of": "YYYY-MM-DD", "note": ""}
4. 只用規範指定的來源。你必須實際開啟頁面才能填「已開原文」；只看到搜尋摘要填「僅摘要」。
5. 查不到、不確定、或只能憑記憶的，value 填 null、status 填「未查」。不要估計。
6. 數字要寫清楚口徑：GAAP 或非 GAAP、是否含併購、哪個會計期間。寫在 note。
7. 公司一律用 rules.json 的標準代號加名稱（追蹤的台積電是美國掛牌的 TSM；2330 是另一檔證券，不可代替）。
   百分比一律寫百分比數字：379% 寫 379，不寫 3.79。
   `run_schema_version=2` 時不要自行填事件距離或衍生 V1；請填事件 ID 與事件原始時間欄位。程式會從 canonical 事件、日曆與 observations 重算，紀錄自行宣告的衍生值不受信任。舊 schema 1 才保留 `event_within_days`。
   估值的 V2 已停用，請不要填（留 null 或省略）；填了也會被忽略。V1 沒有可查證的來源時留 null。
8. 輸出只有一個 JSON 區塊，前後不要加說明。JSON 之後另起一段，列出「我沒查到的欄位」與「我不確定的欄位」。
9. 不要給買賣建議、目標價或資金配置比例。
